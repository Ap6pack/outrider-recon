# Outrider 4.0.0 release notes

Release date: 2026-09-11

Tag name: `v4.0.0`

Outrider 4.0.0 is the first unified release. The Python package and the Claude
plugin/content bundle now share a single version, superseding the earlier
separate Python `0.3.0` and plugin/content `3.1.0` lines. It is a release
candidate, not a publication notice; maintainers still create the tag, GitHub
release, and package artifacts separately.

## Highlights

- Unified versioning: `pyproject.toml` and `.claude-plugin/plugin.json` are
  released together at `4.0.0`, with one `v<version>` tag and one changelog
  release section.
- First-class URL/path scope rules in the governed scope engine (ADR 0020).
- Scope-wide active-enumeration authorization for unattended runs (ADR 0021).
- Self-healing orchestration — transient retry, bounded passive fallback,
  crash-safe resume, and `outrider repair` (ADR 0022).
- Governed agent-to-agent orchestrator loop, independent advisory verifier, and
  deterministic benchmark harness (ADRs 0017–0019).
- One-command `bootstrap.sh` and a loopback-only Docker portal.

See the [changelog](../../CHANGELOG.md) for the complete 4.0.0 entry.

## Optional dependency structure

Base installs remain minimal and require PyYAML only. Optional extras are:

```bash
python -m pip install outrider_recon-4.0.0-py3-none-any.whl
python -m pip install 'outrider_recon-4.0.0-py3-none-any.whl[web]'
python -m pip install 'outrider_recon-4.0.0-py3-none-any.whl[enrichment]'
python -m pip install 'outrider_recon-4.0.0-py3-none-any.whl[mcp]'
python -m pip install 'outrider_recon-4.0.0-py3-none-any.whl[web,enrichment,mcp]'
```

The web extra installs FastAPI, Uvicorn, and HTTPX. Enrichment installs HTTPX.
MCP installs the MCP framework and HTTPX.

## Limitations

The web plane is loopback-only, single-operator, and unauthenticated. The
control token is a local mutation guard, not identity. The release does not add
remote hosting, reverse-proxy deployment, multiuser operation, background jobs,
reports, exports, arbitrary MCP servers, or arbitrary provider endpoints.

## Upgrade from the 0.3.0 / 3.1.0 lines

Install the 4.0.0 wheel, sdist, or bundle in a clean environment and choose only
the extras required. Existing run-folder schemas remain version 1, and artifacts
produced by the earlier separate versions remain readable. Going forward, expect
a single `v<version>` tag and one changelog section per release.
